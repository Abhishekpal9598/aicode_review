A step-by-step guide to deploying the **AI Code Review Platform** to production using **GitHub**, **Render** (Backend API), and **Vercel** (Frontend Client).

## 2. Cloud Infrastructure Prerequisites

### 2.1 MongoDB Atlas Setup
1. Log in to [MongoDB Atlas](https://cloud.mongodb.com/).
2. Create or select a cluster (e.g., M0 Free Tier or dedicated M10+).
3. **Database Access**:
   - Go to **Security** $\rightarrow$ **Database Access**.
   - Create a database user (e.g. `aicode_admin`).
   - Use a strong, autogenerated password (avoid special characters that require URL-encoding, or URL-encode them).
   - Assign the built-in role **Read and write to any database**.
4. **Network Access**:
   - Go to **Security** $\rightarrow$ **Network Access**.
   - Add IP Address `0.0.0.0/0` (Allow Access from Anywhere) to permit serverless/PaaS platforms like Render to connect.
5. **Connection String**:
   - Go to **Deployment** $\rightarrow$ **Database** $\rightarrow$ Click **Connect**.
   - Choose **Drivers** (Node.js).
   - Copy the URI: `mongodb+srv://<username>:<password>@cluster0.mongodb.net/aicode_review?retryWrites=true&w=majority`.

### 2.2 Google Gemini API Setup
1. Log in to [Google AI Studio](https://aistudio.google.com/).
2. Click **Get API key** $\rightarrow$ **Create API key in new project**.
3. Copy the API key string (e.g. `AIza...`).
4. Ensure your project has quota access for model `gemini-3.5-flash`.

## 3. Backend Deployment (Render)

### 3.1 Create Render Web Service
1. Log in to the [Render Dashboard](https://dashboard.render.com/).
2. Click **New +** $\rightarrow$ Select **Web Service**.
3. Connect your GitHub repository: `https://github.com/Abhishekpal9598/aicode_review`.

### 3.2 Configure Service Settings
| Setting Field | Value | Notes |
|---|---|---|
| **Name** | `aicode-review-api` | Or your preferred service name |
| **Region** | Choose closest to database | e.g. Frankfurt, Oregon, Singapore |
| **Branch** | `main` | Production branch |
| **Root Directory** | `server` | **Critical**: Points to backend directory |
| **Runtime** | `Node` | Node.js 20+ |
| **Build Command** | `npm install` | Installs backend dependencies |
| **Start Command** | `npm start` | Runs `node src/server.js` |
| **Plan Type** | Free or Starter ($7/mo) | Starter recommended for zero sleep/latency |

### 3.3 Set Backend Environment Variables
In the Render service settings, navigate to **Environment** and add:

| Variable Name | Required | Example / Recommended Value | Description |
|---|---|---|---|
| `NODE_ENV` | **YES** | `production` | Enables strict security mode |
| `PORT` | Auto | (Leave blank or set `5001`) | Render sets `PORT` dynamically |
| `CLIENT_URL` | **YES** | `https://your-app.vercel.app` | Production frontend domain for CORS |
| `MONGODB_URI` | **YES** | `mongodb+srv://user:pass@cluster.mongodb.net/aicode_review?retryWrites=true&w=majority` | Production MongoDB Atlas URI |
| `JWT_SECRET` | **YES** | `9f83b2a7c4e1605d8b72e4a9f3c1508e6d2b4a7c8e1f0a2d3b4c5e6f7a8b9c0d` | $\ge 32$ chars, high entropy, no placeholders |
| `JWT_EXPIRES_IN` | No | `15m` | Access token lifespan |
| `GEMINI_API_KEY` | **YES** | `AIza...` | Google Gemini API key |
| `GEMINI_MODEL` | No | `gemini-3.5-flash` | Configured AI model |
| `GEMINI_TIMEOUT_MS` | No | `30000` | Max timeout for AI requests (ms) |
| `TRUST_PROXY` | No | `1` | Trusts single reverse proxy hop (Render) |
| `HEALTH_RATE_LIMIT_MAX` | No | `60` | Max health requests/min per IP |

4. Click **Deploy Web Service**.
5. Once built, verify by visiting `https://your-api.onrender.com/api/v1/health`.
   - Expected response: `{"success": true, "status": "healthy", "database": {"connected": true}, "ai": {"configured": true}}`.

## 4. Frontend Deployment (Vercel)

### 4.1 Create Vercel Project
1. Log in to [Vercel](https://vercel.com/).
2. Click **Add New...** $\rightarrow$ **Project**.
3. Import the GitHub repository: `https://github.com/Abhishekpal9598/aicode_review`.

### 4.2 Configure Build & Output Settings
| Configuration Field | Value | Notes |
|---|---|---|
| **Framework Preset** | `Vite` | Auto-detects Vite |
| **Root Directory** | `client` | **Critical**: Points to client directory |
| **Build Command** | `npm run build` | Runs `vite build` |
| **Output Directory** | `dist` | Generated build assets |
| **Install Command** | `npm install` | Installs client dependencies |

### 4.3 Configure SPA Routing & API Proxy (`vercel.json`)
To ensure deep-linking works (avoiding HTTP 404 on refresh) and to handle cookies under same-origin semantics, create or configure `client/vercel.json`:

```json
{
  "rewrites": [
    {
      "source": "/api/(.*)",
      "destination": "https://your-api.onrender.com/api/$1"
    },
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

### 4.4 Set Frontend Environment Variables
In the Vercel project settings, navigate to **Settings** $\rightarrow$ **Environment Variables**:

| Variable Name | Value | Purpose |
|---|---|---|
| `VITE_API_BASE_URL` | `/api` | Relative API path (proxied by Vercel rewrites) |

*(If NOT using Vercel rewrites, set `VITE_API_BASE_URL` to your full Render backend URL: `https://your-api.onrender.com/api`).*

5. Click **Deploy**.
6. Note your assigned Vercel URL (e.g. `https://your-app.vercel.app`).
7. Update `CLIENT_URL` in your **Render Environment Variables** to match this exact domain!

## 5. Cross-Domain Authentication & Cookie Strategy

The application uses secure, HttpOnly cookies with `SameSite=Strict` and CSRF header validation (`X-Requested-With: XMLHttpRequest`).

### Two Supported Deployment Patterns

#### Pattern A: Vercel Rewrite Proxy (Recommended)
- **Frontend**: `https://aicode.vercel.app`
- **Vercel Rewrites**: Routes `/api/*` to `https://aicode-server.onrender.com/api/*`.
- **Advantages**:
  - The browser interacts with the API under the exact same domain (`https://aicode.vercel.app/api/*`).
  - `SameSite=Strict` cookies work natively with 100% browser compatibility.
  - No third-party cookie blocking in Safari, Chrome Incognito, or iOS WebKit.
  - Zero CORS preflight (`OPTIONS`) round-trips for simpler requests.

#### Pattern B: Direct Cross-Domain
- **Frontend**: `https://aicode.vercel.app`
- **Backend**: `https://aicode-server.onrender.com`
- **Considerations**:
  - `VITE_API_BASE_URL` is set to `https://aicode-server.onrender.com/api`.
  - In `server/src/app.js`, CORS must have `origin: https://aicode.vercel.app` and `credentials: true`.
  - Note: Cross-domain cookie sharing requires cookies to use `SameSite=None; Secure`. Bearer token authentication via `Authorization: Bearer <token>` is fully supported by the API client and works seamlessly across separate domains.

## 6. Post-Deployment Verification Protocol

Run through this checklist after deploying both frontend and backend:

1. **Uptime & Health**:
   ```bash
   curl -i https://your-api.onrender.com/api/v1/health
   # Must return HTTP 200 with database: { connected: true } and ai: { configured: true }
   ```

2. **Frontend Loading**:
   - Open `https://your-app.vercel.app/` in a clean browser window.
   - Verify page renders cybernetic dark UI, Monaco editor mounts without console errors.

3. **User Registration & Login**:
   - Register a new account (`name`, `email`, strong password like `P@ssw0rd2026!`).
   - Confirm automatic redirect to `/dashboard`.
   - Verify user profile is returned on `GET /api/v1/auth/me`.

4. **Static Code Analysis**:
   - Navigate to `/review`.
   - Paste a code snippet (e.g. Python quicksort).
   - Click **Analyze Code**.
   - Confirm instant static analysis results, category scores, and findings panel.

5. **AI Review Generation**:
   - Click **Submit AI Review**.
   - Verify loading progression indicator.
   - Confirm AI review results, executive summary, and suggested refactored code.

6. **Session Invalidation on Logout**:
   - Click **Logout**.
   - Confirm redirection to landing/login page.
   - Verify subsequent requests without login are rejected with HTTP 401.

## 7. Common Deployment Errors & Solutions

### Error 1: CORS Policy Error in Browser Console
- **Symptom**: `Access to fetch at 'https://...' from origin 'https://...' has been blocked by CORS policy`.
- **Cause**: The `CLIENT_URL` environment variable on Render does not match the frontend domain, or contains a trailing slash.
- **Fix**: Set `CLIENT_URL` on Render to `https://your-app.vercel.app` (without trailing slash) and trigger a redeploy.

### Error 2: MongooseServerSelectionError / Database Unavailable
- **Symptom**: Health check returns HTTP 503 degraded, or logs show `MongoServerSelectionError`.
- **Cause**: MongoDB Atlas Network Access whitelist does not allow incoming connections from Render.
- **Fix**: In MongoDB Atlas, go to **Network Access** $\rightarrow$ Add IP `0.0.0.0/0`. Verify username and password in `MONGODB_URI`.

### Error 3: Server Exits on Startup with ZodError on JWT_SECRET
- **Symptom**: Render logs show `JWT_SECRET must be at least 32 characters long` or `JWT_SECRET cannot use default or placeholder secret in production`.
- **Cause**: Phase 17A strict production security rule prevents the server from booting in production mode with a weak or default key.
- **Fix**: Generate a strong 64-character random hex string:
  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```
  Set this value as `JWT_SECRET` in Render.

### Error 4: HTTP 404 on Page Refresh on Vercel
- **Symptom**: Navigating to `https://your-app.vercel.app/reviews` works, but refreshing the page returns `404 Not Found`.
- **Cause**: Single Page Applications require the host to route all paths back to `index.html`.
- **Fix**: Add the SPA rewrite rule to `client/vercel.json`:
  ```json
  { "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
  ```
